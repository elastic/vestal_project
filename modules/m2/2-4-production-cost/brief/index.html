Lab 2.4: Production cost

Every LLM call costs money. You will measure that cost, reduce it with a semantic cache, and route cheaper queries to a fast model tier — without sacrificing answer quality.

The problem

Cortex Bank's compliance assistant handles thousands of queries per day. Many are near-duplicates. Generating a fresh answer for each one is expensive and slow.

Two levers reduce cost: caching (skip generation for seen questions) and routing (send simple questions to cheaper models).

What you will do

  • Build 1 — Query transactions: Write ES|QL queries to analyse the synthetic transaction log.
  • Build 2 — Semantic cache: Build a similarity-based cache. Tune the threshold to balance hit rate vs. correctness.
  • Build 3 — Route by complexity: Classify queries as single-hop or multi-hop. Route single-hop to a faster model.
  • Defend: Calculate daily savings from the cache and justify the routing decision based on accuracy.

Cost model

LeverMetricTarget
Semantic cacheHeldout hit rate≥ 0.50
Fast-tier routingSingle-hop accuracy≥ 0.80

Daily savings = floor(volume × hit_rate × cost_per_call / 100)

Key concepts

  • Semantic cache — match incoming queries by embedding similarity; serve cached answers above threshold
  • Similarity threshold — too low → near-misses hit (wrong answer); too high → paraphrases miss (wasted calls)
  • Query classification — single-hop (one fact lookup) vs multi-hop (reasoning across documents)
