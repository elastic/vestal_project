Lab 2.4: Production cost

Every LLM call costs money. You will measure that cost, reduce it with a semantic cache, and route cheaper queries to a fast model tier, without sacrificing answer quality.

Tip: Select Hide Instructions in the top bar to give the Brief full width.

The problem

Before the cache, Tina pays for the same question twice. Two paraphrases from this lab's start state:

generation call 2477 ms | How long must Cortex Bank keep
                          customer identification records?
generation call 2205 ms | What is the retention period for
                          CIP records at Cortex Bank?

Both ask about the same records, and each paid for its own generation call. Every call is billed, and most of Tina's questions are lookups a cheaper model could answer.

Answer from data, not a model

A question whose answer is a count or a sum over structured data never needs generation. An ES|QL query answers it for free, and exactly.

QuestionAnswered byModel calls
How many transactions over a threshold came from one country last month?An ES|QL query over cortex-transactionsNone
What does the retention policy require for identification records?Retrieval, then generationOne

The semantic cache

A semantic cache matches an incoming query to one already answered by embedding similarity. Above a similarity threshold it serves the cached answer and skips generation; below it, it generates and stores the new answer.

ThresholdWhat goes wrongCost
Too lowA near-miss (same domain, different question) hitsThe analyst gets an answer to a different question
Too highA paraphrase missesA generation call paid for again

Route by complexity

Most of Tina's questions are one-fact lookups that a cheaper model answers as well as a strong one. A router reads the question text and picks the tier with no model call: a model classifier would spend a call to save one.

Query typeExample shapeTier
Single-hopOne fact from one documentFast, if its answer accuracy holds
Multi-partReasoning across documentsStrong

Decision rule

Your own measurements decide each row.

WhenThen
A query paraphrases one already answeredServe the cached answer; no generation call
Same domain, different question (a near-miss)Miss and generate
Fast-tier answer accuracy is 0.8 or higherRoute single-hop lookups to the fast tier
Below 0.8, or nothing sent fastRoute nothing to the fast tier
AlwaysMulti-part analysis goes to the strong tier

Daily savings = floor(daily volume × hit rate × cost per call in cents / 100)

What done looks like

  • ES|QL: all 3 queries return the reference rows; sums within 0.1%
  • Cache: at most 1 of 12 outcomes wrong, 0 near-misses served, one document per miss
  • Router: at least 10 of 12 to the right tier, the env model per tier, one live fast-tier call
  • Defend: Question 1 within $1; Questions 2 and 3 follow from your fast-tier answer accuracy and the 0.8 bar
