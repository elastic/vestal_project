Lab 4.3: Multi-turn state and agents outside Kibana

Tina now answers the desk all day, and not only in Kibana. An analyst's follow-up broke after a reconnect, and another analyst wants Claude Code to open cases with Tina's tools. Before the desk relies on either, you need to know what a conversation carries and what changes when the tools leave Kibana.

Tip: Select Hide Instructions in the top bar to give the Brief full width.

The problem

The turn reached Tina without the conversation it belonged to. "That check" and "those" had pointed at an account, a window and an amount from earlier turns. On their own they point at nothing, so Tina asked for the account and the window the analyst had already given her.

The same gap opens wider when another agent calls Tina's tools. Each call arrives alone, with no conversation behind it and none of Tina's rules.

Conversation state

conversation_id 7f3c...
  round 1   analyst turn     "Check account 3456 ... last 30 days"
            tool calls       cortex.structuring_deposits(3456, 30)
                             + their results
            answer           Tina's text
  round 2   analyst turn     "Of those, which were above 9,000?"
            ...
  round 3   analyst turn     sent with the id: all rounds above come back

Agent Builder stores every round of a conversation: the analyst's turn, each tool call with its result, and Tina's answer. Send the conversation_id with a new turn and the model reads all of it again. Leave the id out and the turn starts a new conversation with nothing behind it.

What a turn without its history does is up to the model. It may ask for the missing account, call a tool without it, guess a value, or answer from nothing. Read the route to see which.

Reformulation

depends on earlier turns   "Run that check again and list only those"
stands alone               "Check account 3456 for cash deposits just under
                            10,000 in the last 30 days and list those above
                            9,000, newest first"

A reformulated turn carries everything the earlier turns supplied: the account, the window, the amount. It works in a new conversation, from a scheduled job, or from another agent, because it needs no history.

The test is the route. Sent alone, the sentence should make Tina call the same tool with the same values the original turn relied on.

The endpoint

<kibana>/api/agent_builder/mcp?namespace=cortex
  transport   HTTP (streamable)
  header      Authorization: ApiKey <encoded key>
  tools       cortex.open_case  ->  cortex_open_case

Agent Builder serves its tools over the Model Context Protocol at one Kibana endpoint. Any MCP client that speaks HTTP can list and call them: Claude Code, a Python client, a LangGraph agent.

Agent Builder ids are dotted; over MCP the dots become underscores. A client that asks for cortex.open_case by name finds nothing.

MCP exposes tools, not the agent

in Kibana      analyst -> Tina (instructions, skill, rules) -> tools
over MCP       analyst -> Claude Code (its own planning)     -> tools
                         Tina is not involved

Over MCP the client gets Tina's tools, not Tina. The coding agent decides which tool to call and with what values. Tina's instructions, her skill and her escalation rule do not apply to those calls.

Each MCP call is stateless: one request, one answer. No Agent Builder conversation is opened, and the workflow runs it starts carry no agent id. The task's turns live in the client's own session, which for Claude Code is a file under ~/.claude/projects/.

Exposure versus authority

Decided byAnswers
ExposureThe namespace on the endpointWhich tools a client can see
AuthorityThe key in the headerWhat each call can read or write

Tools run as the caller. A workflow tool called with a key that cannot write to the case index runs, fails at its write step, and reports the failure in its result. A tool can be listed and still unable to finish.

Least privilege for a coding agent is a key with read on the indices the tools query, write only where a tool must write, and no index wildcards. Your shell's admin key works too, which is exactly why it is the wrong one to hand over.

Inbound and outbound MCP

inbound    outside client  --calls-->  Agent Builder's tools
outbound   Agent Builder   --calls-->  another server's tools, as its own

This lab is inbound: Claude Code calls Cortex's tools. Outbound is the other direction, where an agent in Agent Builder uses an external MCP server's tools as if they were its own. The connection details in this lab, namespace, header and underscore names, belong to the inbound side.

The coding agent's model route

Claude Code  ->  curriculum gateway  ->  model
  env block in ~/env:  ANTHROPIC_BASE_URL, ANTHROPIC_AUTH_TOKEN, ANTHROPIC_MODEL, ...

Claude Code reaches its model through the lab's gateway with a key issued for this sandbox. The variables are set in your shell; you do not need to touch them. The Elastic CLI, in technical preview, is another way to reach Agent Builder from a terminal; this lab does not use it.

Decision rule

Take the first row that applies.

QuestionAnswered by
Does this turn need earlier turns?Send the conversation_id, or rewrite the turn so it stands alone
Which tools can a client see?The namespace on the endpoint
What can a call touch?The key's privileges: the tool runs as the caller
Who plans the steps?The client. Over MCP, Tina's instructions do not apply

Exposure is the namespace; authority is the key.

What done looks like

  • Your reformulation of turn 3, sent alone, takes Tina's route with the planted account and window on at least 2 of 3 runs (aim for 3)
  • Your persisted set and reset outcome match the stored conversations, your own replay included
  • cortex-mcp lists only Cortex's tools, runs a read tool, and is refused a write to cortex-ref-accounts
  • Three securities_layering cases, each from a cortex-open-case run your Claude Code session started over MCP

Also checked:

  • The key: read on the four indices the tools query, write only on the case and audit indices, no wildcards, no all or manage
  • The session: cortex_securities_layering over the last 10 days, cortex_open_case per account, no direct writes from the shell
