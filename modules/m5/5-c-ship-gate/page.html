Capstone 5.C: The ship gate

Cortex Bank and Trust's platform team has staged a change to Tina and asks you to sign it off for production. You have the harness, the before-and-after rules and the controls from Labs 5.1 to 5.4. Nobody tells you what the change touched.

Tip: Select Hide Instructions in the top bar to give the Brief full width.

The scenario

The change request in your sandbox (~/cortex-eval/change-request.md) states what the change improves, the number that keeps that gain, and the limit on any category's routing accuracy. It is written to be read as a pitch: it does not say what else the change did. Your job is the one a release owner has before anything reaches the desk: find out, close it or undo it, measure again, and decide.

Tina's start state before the change, on the same test set you will measure with. Routing is already perfect, so the only thing a change can improve in these numbers is cost; the only thing it can do to routing is lower it. Your own runs print the same table by category.
